DATA STRUCTURE 01 / 07

二叉堆 Binary Heap

用完全二叉树维护堆序：父节点的键不大于孩子；树直接存放在连续数组里。

insert(4)：从叶节点上滤parent = ⌊(i−1)/2⌋
数组下标就是父子关系
连续数组 · 完全二叉树 · 堆序
操作实现动作复杂度
push末尾插入，逐层上滤O(log n)
extract-min末元素补根，逐层下滤O(log n)
decrease-key经 pos[v] 定位并上滤O(log n)
DIJKSTRA COST

结构简单、缓存友好；每次操作都要沿树高移动元素，是后续所有实现的工程基线。

DATA STRUCTURE 02 / 07

4-ary 堆 4-ary Heap

把每个节点的孩子数从 2 增加到 4，以更多孩子比较换取更浅的树。

insert(4)：更短的上滤路径parent = ⌊(i−1)/4⌋
树高从 log₂n 变为 log₄n
连续数组 · 四叉完全树 · 更浅的树
操作实现动作复杂度
push末尾插入，四叉树上滤O(log n)
extract-min补根，比较 4 个孩子并下滤O(log n)
decrease-key经 pos[v] 定位并上滤O(log n)
DIJKSTRA COST

渐近阶不变，但指针跳转和树高减少；连续内存让更浅的树转化为实际缓存收益。

DATA STRUCTURE 03 / 07

左偏堆 Leftist Heap

以 npl（null path length）维持“左侧不短于右侧”，让合并主要沿较短的右脊进行。

meld(A, B)：合并并修复 nplnpl(left) ≥ npl(right)
比较根，递归合并右脊
指针节点 · npl 元数据 · 可合并堆
操作实现动作复杂度
push单节点与根 meldO(log n)
extract-min删根，meld 左右子树O(log n)
decrease-key切断、修复祖先 npl，再 meldO(log n)
DIJKSTRA COST

右脊短保证复杂度，但每次 meld 都有指针跳转和 npl 维护；decrease-key 还需切断并向上修复。

DATA STRUCTURE 04 / 07

斜堆 Skew Heap

不再记录 npl；每次 meld 后无条件交换左右孩子，用自调整换取摊还性能。

meld(A, B)：与左偏堆对照always swap children
相同输入，不同交换规则
指针节点 · 无 npl · 自调整
操作实现动作复杂度
push单节点与根 meldO(log n) 摊还
extract-min删根，meld 左右子树O(log n) 摊还
decrease-key从父节点切断，再 meldO(log n) 摊还
DIJKSTRA COST

省去 npl 写入和祖先修复，代码更简单；但树形不固定，仍然依赖大量指针操作。

DATA STRUCTURE 05 / 07

二项堆 Binomial Heap

用按度数排列的二项树森林维护堆序；同度树链接类似二进制加法的进位。

meld：B0 → B1 → B2Bk 含 2ᵏ 个节点
根链表按 degree 组织
二项树森林 · degree 根链表 · 同度链接
操作实现动作复杂度
push插入 B0，与根链表 meldO(log n)
extract-min扫描最小根，孩子反转后 meldO(log n)
decrease-key与父节点交换 key / id 并上移O(log n)
DIJKSTRA COST

同度链接控制树数，但 pop 要扫描根链表并合并孩子；交换 key / id 还需同步 nodes 映射。

DATA STRUCTURE 06 / 07

Fibonacci 堆 Fibonacci Heap

多棵满足堆序的树组成循环双向根链表，min 指向最小根；插入和减少键尽量推迟整理。

cut → pop → consolidatemark + cascading cut
延迟整理换来更好的摊还界
根链表 · mark / 级联切断 · consolidate
操作实现动作复杂度
push直接插入根链表O(1)
extract-min孩子入根，consolidate 同度树O(log n) 摊还
decrease-keycut；必要时级联切断并标记O(1) 摊还
DIJKSTRA COST

理论 Dijkstra 界达到 O(m+n log n)；代价是每次 pop 的整理、根链表和大量指针维护。

DATA STRUCTURE 07 / 07

radix heap 单调优先队列

利用非负整数键和 extract-min 的单调性，按 k XOR last 的最高有效位分桶。

上一次弹出的键 last10最低非空桶将决定下一个 last
bucket(k) = 0k = last⌊log₂(k XOR last)⌋ + 1k ≠ last
33 个桶 · 32 位整数键
整数键 · 单调 last · 按位分桶
操作实现动作复杂度
push按 k XOR last 直接放桶O(1) 摊还
extract-min最低桶找 min，更新 last 并重分桶O(1) 摊还
decrease-key从原桶删除，按新键重新放桶O(1) 摊还
DIJKSTRA COST

每个元素最多跨桶 32 次；Dijkstra 整体为 O(m+n log C)，C 为键值上界。依赖整数键和单调操作，不是通用比较堆。

APPENDIX 05 / FAQ

可能被问到的问题

把实验口径和结论边界放在同一页，便于问答时快速定位。

01

为什么 CTR / USA 主表只有 100 对？

完整组合耗时较长，主表控制预算；随后已用 fib / four / radix 补跑 1000 对，排名一致。

02

radix 参加比较公平吗？

它利用题目已有的整数键和单调性，单独归类为单调优先队列；比较堆内部结论不受影响。

03

为什么 4-ary 快于二叉堆？

树更浅、连续数组缓存更友好；12/12 个数据集上耗时降低约 7.0%–11.2%。

04

为什么 Fibonacci 反而最慢？

decrease-key 只占 pop 的约 5.8%–14.4%；每次 pop 的 consolidate 和指针常数占主导。

05

内存占用是多少？

USA CSR 约 562 MB；独立进程峰值：four 832 MB、radix 850 MB、Fibonacci 1939 MB。

06

还能继续加速吗？

双向 Dijkstra、A*、ALT、contraction hierarchies。减少搜索空间比继续微调堆常数更有效。
